# Светлица — svet-kp.ru

Статический сайт апартаментов в Красной Поляне. Источник изменений — этот репозиторий.

- `public/` — готовые файлы для хостинга, без сборки и авторизации.
- `public/index.html` — главная страница, правила, инструкции и форма бронирования.
- `public/booking-v3.js` — формирование ссылки с датами и количеством гостей.
- `public/guest/content.json` — отдельный гостевой справочник, русский и английский.
- `public/media/guide/` — общие фотографии техники для обоих справочников.
- `scripts/deploy.sh` — установка с резервной копией.
- `scripts/update.sh` — получение изменений из `main` и установка.
- `scripts/validate.py` — проверка ресурсов, JSON, sitemap и согласованности ссылок.

Node.js, npm, PHP и база данных для работы сайта не нужны. Для Git-установки на хостинге нужны Bash, Git и стандартные утилиты Linux. Если есть rsync, он используется; иначе — копирование файлов.

## Первая установка на REG.RU

В панели хостинга сначала добавьте `svet-kp.ru`, настройте DNS и HTTPS. Посмотрите **точный полный путь** к корневой папке сайта. Скрипт не угадывает этот путь и не создаёт домен или SSL-сертификат.

В Shell/SSH:

```bash
git --version
git clone https://github.com/gselfman/svet-kp.git "$HOME/svet-kp"
bash "$HOME/svet-kp/scripts/deploy.sh"
```

При запросе вставьте полный путь к корню `svet-kp.ru` из панели REG.RU. Скрипт запомнит его для дальнейших обновлений. Если `$HOME/svet-kp` уже существует, не запускайте `git clone` поверх него: проверьте, какой проект там находится.

Репозиторий хранится **вне** публичной папки. В корень сайта копируется только `public/`. Перед каждой установкой создаётся архив текущего сайта в `$HOME/svet-kp-backups/`. На первой установке чужие файлы не удаляются. При дальнейших установках удаляются только файлы, ранее установленные этим скриптом и удалённые из `public/` в Git.

Конфигурация установки находится в `$HOME/.config/svet-kp/`; она не отправляется в GitHub. Не меняйте файлы прямо на хостинге — следующее обновление заменит управляемые файлы содержимым Git.

## Обновление сайта

После внесения изменений в GitHub и попадания их в `main`:

```bash
bash "$HOME/svet-kp/scripts/update.sh"
```

Обновление выполняется по этой команде, не автоматически после коммита. Скрипт не запрашивает пароль GitHub для чтения публичного репозитория. Если есть локальные изменения, обновление останавливается и не перезаписывает их.

## Проверка после установки

```bash
curl -I https://svet-kp.ru/
curl -I https://svet-kp.ru/booking-v3.js
curl -I https://svet-kp.ru/media/guide/hammam-control-panel-v2.webp
```

Нужен ответ 200. Откройте сайт в приватном окне без аккаунта ChatGPT. Проверьте фото справочника, галерею и переход к бронированию. Если появляется пароль, отключите защиту каталога в панели хостинга и проверьте родительские `.htaccess`. В этом проекте авторизации нет.

Внешние сервисы: модуль бронирования, Яндекс Карты и Google Fonts. Паролей сервера, токенов GitHub и кодов key-box в репозитории быть не должно. Гостевой справочник публичный и содержит пароль Wi-Fi.

## Работа с исходниками

Редактируйте `public/`, сохраняйте изменения в ветку и объединяйте их в `main`. Вносите правки правил и инструкций одновременно в главную страницу, `guest/content.json` и JSON-LD, если соответствующий текст там есть. Обновляйте версии CSS/JS в HTML после изменений.

Проверки перед коммитом:

```bash
python3 scripts/validate.py
node --check public/app.js
node --check public/booking-v3.js
node --check public/guest/app.js
bash -n scripts/deploy.sh scripts/update.sh
```

Python и Node.js нужны только для разработки и проверок, не для работы сайта.

Фотографии проходили генеративную обработку; важные детали следует сверять с реальным объектом. Социальный коллаж — постановочная иллюстрация. Техническая SEO-подготовка не гарантирует позиции и индексацию; после запуска добавьте сайт и sitemap в Google Search Console и Яндекс Вебмастер.
